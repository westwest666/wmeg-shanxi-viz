# 00 · 可视化网站改版方案总览（四方商议结果）

> 2026-10-18 · Lead 汇总 · 参与方：viz-research（A 调研）、critique（B 诊断）、model-viz2（C 模型讨论）、tech3d2（D 3D 重做），Lead 负责机理数据抽取与原型。
> 本文件只做方案与计划，**尚未改动正式站**；两个可交互原型见 design/ 目录。

---

## 0 一句话结论

现站的问题不是"功能少"，而是**它是一个按字段做面板的数据看板，不是按问题做叙事的可视化**：空间上缺"关系层"（流/波前）、时间上缺"连续层"（尾迹/插值/事件）、叙事上缺"引导层"（结论先行/讲解）。
改版不推翻静态站，主线是：**首页讲清结论 → 传播剧场看过程 → 时空立方体看结构 → 城市页看预测与不确定性 → 模型页讲机理**。

## 1 现状判决（B 的硬证据，节选 12 条）

1. 网络节点半径只在 buildNetwork 计算一次（app.js:573-586），播放时只改颜色 —— README 承诺的"节点大小 ∝ 病例"在播放中不成立。
2. 播放每帧整页重建表格/卡片/图表（app.js:645-685），叠加 style.css:59 的 0.25 s fill 过渡 → 颜色被渲染成中间色，节奏感全失。
3. 色阶 sqrt(v/18) 把 76.6% 的"城-日"压进前 2 档；v≥18 全部截断为同一红；q99=18.57 而 max=49.1；49% 的日期"全省最大 < 5 例"，半年地图无信号。
4. 图例（style.css:65）与实际填色（app.js:88-93）是两套 RGB。
5. 全站没有任何一张图同时画两个城市；唯一跨城信息是数字表格。
6. 人口未标准化：raw 计数地图有一半在画人口；按人口率重排，晋城 2.43×、太原 0.49×。
7. 3D 五个技术病灶：柱高与颜色同源（无第三维）、1:5 垂直夸张 + 53° 俯角、按面平均深度排序、标签最后画、粒子穿模、固定 1000×690 无 DPR。
8. 默认日期 2019-01-15 恰好错过峰值 2019-12-28（166.9 例，是 2015 峰值 40.0 的 4.2 倍）。
9. 城市页最大版面给了天气动画；2016-07-09 长治"大暴雨 + 0 例"，情绪与数据相反。
10. 模型解释整体缺席：mech 分支、峰值命中 0.636、机理 RMSE 3.52 都没上屏。
11. 口径风险：原始 RMSE 2.1611 比持续性 2.1225 差 1.8%，只有 α=0.25 校准后 2.0125 才低 5.2%，页面用相对数绕开了绝对比较。
12. 播放没有"事件地标"（流感季/春节/寒潮），1826 天拖两下就迷路。

## 2 模型讨论：β、C、扇形到底能说什么（C 的实测结论）

Lead 已从 15 个断点抽取全期机理数据（data/mech_data.json，727 KB），包含 β(t)[1826×11]、接触矩阵 C 的 19 条接壤边权重、自留份额、测试段 15 种子分位、逐日集成预测与真值、19 对滞后互相关。

**必须修正的四个事实**（直接影响可视化设计）：
1. **C 不是动态传播流量**：19 条边权重的时间 std 仅 2.4e-4~9.3e-4（相对 <0.4%），且 flowDaily ≈ 0.5·[1/(deg_a+1)+1/(deg_b+1)]，最大偏差 0.00102；config 里 graph_uniform=1。它本质是"度归一化邻接 + 微扰"的准静态注意权重，**不能做实时流量动画**。
2. **selfShare = 1/(邻居数+1)**：2 邻居城 0.334、5 邻居城 0.167，偏差 <0.0015，是度数算术，不是学到的本地接触占比。
3. **β 只能当相对强度**：β 城市均值 0.092–0.353（3.8×），与 log 城市病例 r=0.805、与 log 人口 r=0.161；月均仅 0.182–0.223（±10%）；论文自认与 C 存在行列重标定不可辨识，跨种子相关 0.56–0.62。**能说时间形状/城市排序，不能说绝对值、不能当流行病学传播率**。
4. **15 种子扇形是"训练随机性"**，不是置信区间；网页必须标注口径。

**三个数字口径不可混用**：2.1611（132 个城×步长单元格等权，论文口径）/ 2.7364（池化 RMSE，mech_data.sanity 复算一致）/ 2.5559（374 天逐日序列口径）。网页标"模型拟合"时必须写清用哪一个。

**时滞相关**：leadLag 的 |lag| 中位是 4 天（B 文档的 7 天是"周尺度去季节"另一口径）；leadLag 由全期 1826 天计算，**只可用于展示，不可喂进训练**（测试段泄漏）。

**模型改进方向（讨论结论，按优先级）**：
- A 校准内生化（12 步全负于持续性、R 与 Δ 反号、α_h 0.03→0.34）——改后可视化应把"校准前/后 vs 持续性"并列。
- B 有向时滞图/流动先验（代码 GRAPH_LAG/MIG_DIR 已在、百度迁徙可用；必须在训练段估计时滞）。
- C 口径与人口标准化（这同时是 B 文档 76.6% 色阶问题的根）。
- D 分位数预测/峰值项（可选）。

## 3 借鉴：最值得抄的 5 个设计（A 调研）

1. **时空立方体**（z 轴=时间）：一次解决"变化过程 + 城际关系 + 3D 新意"三个痛点。
2. **传播粒子流 + 有向弧线 + 扩散环**：城际传播的正解；方向来自数据时滞，模型只做结构底纹。
3. **预测扇形图 + 误差矩阵**：把"预测"变成一团可能，花最少力气把模型页做专业。
4. **Hovmöller 时间×城市波图 + 波前等值线**：最便宜的新意，一眼看出谁先到峰。
5. **scrollytelling 讲解模式 + 流感年钟**：治"没新意/不够高级"。

参考案例：CDC FluView、COVID-19 Forecast Hub、Nextstrain、NYT《How the Virus Got Out》、Flowmap.blue、earth.nullschool、deck.gl TripsLayer、Zoonotic Web（IIB 2024 金奖）等（详见 A 文档 24 个案例）。

## 6 分阶段落地计划

### P0（先做，1–2 天，全是前端 + 一次预计算）
1. 首屏故事条（结论 + 3 英雄数字 + 5 年主曲线，共用 state.idx）。
2. 11 城小倍数/时间带（固定全期 x 轴、按峰值日期排序、行尾人口率 + 7 日变化）。
3. 播放引擎：预渲染 + 只移动游标 + 删除 fill 过渡 + 数值插值（目标 ≥55 fps）。
4. 地图双通道 + 人口标准化 + 图例由 JS 常量生成（消除两套 RGB）。
5. 传播剧场嵌入首页（P0 版：结构底纹 + 数据方向光点 + 变化脉冲）。

### P1（3–6 天）
6. 时空立方体替换现有 3D（three.js 原型收敛为正式页）。
7. #/spread 波图 + 到达顺序 + 传播时滞矩阵。
8. 城市页：15 种子扇形 + 邻城对照 + β 曲线 + 邻居压力。
9. #/mechanism 模型解释页（C 结构 vs 扰动、误差分解、峰值命中）。
10. 事件地标与年份/流感季导航；双城对比 #/compare。

### P2（1–2 周）
11. #/story 五章滚动叙事 + 深链；视觉系统（字体/色板/动效预算）；数据分片与性能回归；a11y。

## 7 验收标准

- 30 秒首屏测试：5 名非项目成员中 ≥4 人能答对 ≥3 题（哪年最重/谁先到峰/模型比持续性如何/湿度与 β 关系）。
- 播放：20 天/秒 ≥55 fps、无长任务 >50 ms、无颜色拖影。
- 口径：页面所有 RMSE 标注口径；校准前后与持续性三者并列出现。
- 诚实：C 标注准静态、β 标注相对强度、扇形标注训练随机性、迁徙数据标注 2020 年不匹配、leadLag 标注全期统计非因果。
- 3D：截图评审三项必过（接触阴影/深度雾/标签不穿模）；盲测"比旧版高级" ≥4/5。

## 8 风险与诚实边界

1. C 是准静态注意权重，不能包装成"实时传播流量"（C 文档已给红线话术表）。
2. β 与 C 有行列重标定自由度，β 不能当流行病学传播率。
3. 15 种子扇形 ≠ 置信区间。
4. leadLag 全期计算，仅作视觉引导，不可进训练。
5. 2020 春运迁徙与 2015–2019 年不匹配，只能当结构先验并标注。
6. 三个 RMSE 口径（2.1611 / 2.7364 / 2.5559）不可混用。
7. 3D 时空立方体在 11 城 × 1826 天数据量下需要抽稀/实例化，注意低端机性能。
